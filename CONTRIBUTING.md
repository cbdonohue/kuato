# Contributing

Thanks for helping with Kuato. This guide is the shortest path from a clone to a reviewable pull request.

## Code of conduct

By participating, you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## What this project is

Kuato is a Next.js app that reads public [Sleeper](https://docs.sleeper.com/) draft data and ranks remaining players for a redraft room. It does not write to Sleeper. Auction drafts and dynasty leagues are out of scope unless a change says otherwise.

## Setup

You need Node.js 20+ and npm. Or [open in GitHub Codespaces](https://codespaces.new/cbdonohue/kuato). Create a new codespace (or rebuild) so it uses `.devcontainer` instead of the default image. The container runs `npm ci`, writes `.env.local` (`SITE_PASSWORD=kuato` unless you set a Codespaces secret), starts `npm run dev`, and forwards port 3000.

```bash
git clone https://github.com/cbdonohue/kuato.git
cd kuato
npm ci
cp .env.example .env.local
```

Set `SITE_PASSWORD` in `.env.local`. Optionally set `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` to exercise Ask, Scout, Compare, Review roster, News briefing, Sleepers & fades, and Injury analysis.

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000), sign in, then use **Your drafts** (Sleeper username) or **Mock draft** (Sleeper mock ID). `/debug` redirects to the mock tab.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Next.js dev server |
| `npm run build` | Production build |
| `npm start` | Serve the production build |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Vitest once |
| `npm run test:watch` | Vitest in watch mode |
| `npm run test:coverage` | Vitest with the 80% coverage gates |

Coverage must stay at 80% or higher for statements, branches, functions, and lines. CI runs lint, typecheck, and coverage on every pull request.

## Pull requests

1. Branch from the latest `master`.
2. Keep the change focused. Docs-only, CI-only, and feature work should not share a PR unless they are inseparable.
3. Add or update Vitest coverage for logic you change. UI work should include component tests when the behavior is meaningful.
4. Run `npm run lint`, `npm run typecheck`, and `npm run test:coverage` locally.
5. If you change the live room, replace `docs/live-room.webp` (the README autoplay walkthrough).
6. Fill out the pull request template.

`AGENTS.md` and `CLAUDE.md` are generated by `next dev`. Do not hand-edit them to fight the generator; committing the generated block keeps the tree clean.

## Layout

| Path | Role |
| --- | --- |
| `.devcontainer/` | GitHub Codespaces / Dev Containers (Node 20, auto-starts port 3000) |
| `src/app/` | App Router pages and API routes |
| `src/components/` | Live room, home lookup, coach panel |
| `src/lib/` | Sleeper, ADP, nflverse, scoring, AI, auth |
| `src/proxy.ts` | Session gate for pages and `/api/*` |
| `docs/` | README walkthrough, architecture, and deploy notes |
| `.cursor/rules/` | Cursor project rules for agents (`.mdc`) |

Recommendation scoring lives in `src/lib/recommend.ts`. Live draft assembly is `src/lib/live.ts`. See [docs/architecture.md](docs/architecture.md) for the data flow.

Cursor Agent reads `.cursor/rules/*.mdc`. Keep those rules short and tied to this repo: redraft-only, read-only Sleeper, `src/proxy.ts` instead of `middleware.ts`, colocated Vitest, 80% coverage. Update a rule when an agent repeatedly gets a convention wrong.

## Issues

Use the bug or feature templates. Include a Sleeper draft ID and scoring type when the report depends on a specific room. Do not paste session cookies or API keys.
